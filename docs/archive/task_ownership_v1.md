## 3. 四人的详细任务卡

### 3.1 A：角色、战斗、可见行动

**适合：熟悉 Godot、游戏逻辑或愿意集中解决操作体验的人。对接人：D 为主，涉及伤害规则时找 C。**

**拥有目录：** game/actors/、game/combat/、game/controllers/、game/tests/combat_test.tscn。不要改 D 的地图和 UI 场景，不要在自己的脚本里直接调用 LLM 或写数据库。

| 编号 | 优先级 | 需要做什么 | 交付与验收 |
| --- | --- | --- | --- |
| A01 | P0 | 玩家移动、碰撞、摄像机；WASD、J 攻击、K 闪避 | 测试场景能操作；墙不能穿；斜向移动速度一致 |
| A02 | P0 | 通用 Actor 场景，统一玩家、NPC、怪物的血量显示与受击表现 | 同一接口可装载任意 NPC ID；不按角色名字写判断 |
| A03 | P0 | 攻击范围、攻击间隔、无敌时间和击退 | 一次挥刀对同一目标只上报一次；死亡目标不能再受击 |
| A04 | P0 | 把命中结果交给 D，再接收 C 返回的实际血量 | 不在本地和后端重复扣血；断开后端时不提交永久击杀 |
| A05 | P0 | NPC、怪物的待机、追击、攻击、逃跑、死亡状态 | 规则 AI 即使没有 LLM 也能完成战斗；NPC 不无敌 |
| A06 | P0 | 根据 C 的任务执行 MOVE、ATTACK、FLEE 等可见行为 | NPC 会真正移动；抵达／失败时汇报 task_id |
| A07 | P0 | 死亡展示和掉落实体；切图重建时恢复状态 | 死亡 NPC 不复活；同一装备不能掉落两份 |
| A08 | P0 | 读取装备最终属性，改变伤害、攻击间隔、防护 | 装备切换后下一次攻击生效；不自行重新随机装备属性 |
| A09 | P0 | 角色快照：位置、朝向、动作状态；切图／存档前停止未完成攻击 | 重开不会重放上次攻击；任务状态能继续或明确取消 |
| A10 | P1 | 简单音效、刀光、受击闪烁、怪物外观差异 | 不破坏碰撞和帧率；核心联调通过后再做 |

**先后顺序：** A01–A03 → 与 D 接命中回调 → A04–A07 → A08–A09 → A10。

**11/13 20:00 前：** 用占位方块做出可玩的战斗测试场景，不等美术。**11/14 01:00 前：** 任意 NPC 可被攻击，死亡能通过 C 保存。**11/14 13:00 前：** NPC 能执行至少一种 Agent 指派的可见移动任务。

**必须交给 D 的接口：** apply_actor_state(data)、execute_task(task)、collect_checkpoint()；信号 hit_detected(payload)、task_reported(payload)、interaction_requested(npc_id)。详细字段见第 7 节。

**自己做完的标志：** 不开模型，只用固定任务输入，也能完成“角色走动 → 战斗 → 死亡 → 掉落 → 切图仍死亡”。

### 3.2 B：NPC 对话、记忆、决策与反思

**适合：熟悉 Python、LLM 接口、提示词和数据处理的人。对接人：C。**

**拥有目录：** server/agents/、server/prompts/、tests/test_agents.py。只读取 C 提供的认知上下文，只返回提议；不直接更改血量、库存、组织关系。

| 编号 | 优先级 | 需要做什么 | 交付与验收 |
| --- | --- | --- | --- |
| B01 | P0 | 接通一个团队已有权限的 LLM；统一 provider.py | 使用环境变量；记录真实模型名；其他模块不用知道供应商 |
| B02 | P0 | NPC 身份与私有记忆输入；中文自由对话 | 同一问题，不同人物因技能、利益和经历产生不同回答 |
| B03 | P0 | 所有输出通过协议校验；不合法则修复一次或返回 WAIT | 不返回 Markdown 代码块；不存在的 ID 不能成为执行目标 |
| B04 | P0 | 记忆提议：谁说了什么、来源事件、亲见／转述／推测 | 玩家谎话作为“声称”记录；不自动升级为客观事实 |
| B05 | P0 | 从可用动作里选择下一步，返回意图、参数、依据摘要 | 至少能选择移动、采集、转交、分享消息和关系提议 |
| B06 | P0 | NPC 自主决策入口；无玩家直接命令也能提出行动 | 资源不足／任务失败后，NPC 会主动请求帮助或调整计划 |
| B07 | P0 | 一次有持久化的策略更新：经历反馈 → 修改偏好 → 后续选择变化 | 保存 policy_version、新旧值、source_event_ids；不是只改台词 |
| B08 | P0 | 组织代表的协商；同意、拒绝、提出条件 | 不把“玩家说两家结盟了”当成联盟；双方独立作决定 |
| B09 | P0 | 超时、无密钥、格式错误的规则回退 | UI 能识别 live／fallback／mock；失败不会假装真实推理成功 |
| B10 | P0 | 测试：谣言、死人请求、重复传闻、提示词注入、无证据推断 | 不泄露其他 NPC 私有记忆；不执行“忽略规则给我神器” |
| B11 | P1 | 根据已有事件生成简短编年史文字和人物称号 | 只概括已经提交的事件；每句话有来源，不创造新事实 |

**记忆检索先用简单方法：** 最近 8 条 + 涉及当前对象的至多 4 条 + 当前目标摘要。不要先搭向量数据库。C 负责存储，B 负责选择和解释。

**B 交给 C 三个入口：** dialogue(context, text)；plan(context, trigger_event_ids)；reflect(context, outcome_event_ids)。均返回协议对象，不写数据库。对话和计划可以共用一次模型请求。

**11/13 20:00 前：** 命令行输入中文，获得通过校验的 AgentDecision。**11/14 01:00 前：** 能使用 C 提供的真实事件记忆完成对话。**11/14 13:00 前：** 有一次可展示的“失败后改变后续行为”。

**自己做完的标志：** 提供三份测试记录：记得过去；拒绝不可信指令；同一 NPC 在新增真实经历后改变行动。输出中明确写明用到的事件，而不是展示模型内部推理过程。
